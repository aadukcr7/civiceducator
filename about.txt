==================================================
1) PROJECT IDENTITY
==================================================
Project Name: Civic Education Nepal
Package Name: civic-education-nepal
Version: 1.0.0
Author: Aadii
License: ISC
Repository: https://github.com/aadukcr7/civic.git
Live URL: https://civiceducator.onrender.com/

Short Description:
A full-stack civic learning platform focused on Nepal that teaches constitutional rights, civic duties, and public participation through structured levels, lessons, quizzes, analytics, and admin-managed content.

Primary Goal:
Turn civic education into a measurable and guided learning journey (not just static information pages).

==================================================
2) TECHNOLOGY STACK
==================================================
Runtime and Backend:
- Node.js (engine >=14.0.0)
- Express 4

Frontend Rendering:
- EJS templates (server-side rendered views)
- Static assets served from public/css and public/js

Database and Persistence:
- SQLite3 database file (default: civic_education.db)
- SQLite-backed session storage via connect-sqlite3

Security and Middleware:
- helmet (HTTP security headers + CSP)
- express-rate-limit (global request throttling)
- csurf (CSRF protection using session token)
- express-session (session management)
- bcryptjs (password hashing)
- express-validator (input validation)
- compression (gzip/deflate response compression)
- morgan (HTTP request logging)
- dotenv (environment variable loading)

Dev Tools:
- nodemon (development server auto-reload)
- prettier (formatting)

Deployment:
- Render (Procfile: web: node server.js)

==================================================
3) MAIN APPLICATION BEHAVIOR
==================================================
Core Functional Areas:
- Authentication (register, login, logout)
- User profile and learning history
- Structured learning levels with lesson content
- Level quizzes with adaptive difficulty guidance
- Quiz scoring, progress persistence, and result reporting
- Dashboard analytics (strengths, weak areas, recommendations)
- Authenticated lesson-grounded chatbot assistant
- Admin panel for managing users, levels, lessons, and quiz questions
- Guest-only About page walkthrough

High-Level User Journey:
1. User visits home page.
2. User registers or logs in.
3. User opens levels and studies lesson content.
4. User attempts quiz for a level.
5. App scores answers, stores progress and attempt metrics.
6. User checks dashboard/profile for insights.
7. User can ask the chatbot lesson-grounded questions.
8. Admin can update educational content and manage users.

Middleware:

5) DATA MODEL (SQLITE)
==================================================
Database default file:
- civic_education.db (root-level by default)

Tables:
1) users
- id (PK)
- username (unique)
- email (unique)
- password (hashed)
- is_disabled (0/1)
- created_at

2) progress
- id (PK)
- user_id (FK users.id)
- level_id
- completed (0/1)
- score
- completed_at
- unique(user_id, level_id)

3) quiz_attempts
- id (PK)
- user_id (FK users.id)
- level_id
- score
- correct_count
- total_questions
- duration_seconds
- difficulty (easy|medium|hard expected)
- created_at

Indexes on quiz_attempts:
- (user_id, level_id, created_at DESC)
- (user_id, created_at DESC)

4) sessions
- sid (PK)
- sess
- expired
(used by connect-sqlite3 session store)

6) SECURITY IMPLEMENTATION DETAILS
==================================================
Security Controls Implemented:
- Password hashing with bcryptjs (10 salt rounds)
- Session cookies configured with:
  - httpOnly: true
  - sameSite: lax
  - secure: true in production
- CSRF protection enabled globally after session setup
- Helmet with CSP directives restricting sources
- Rate limiting (100 requests / 15 minutes per IP)
- Input validation using express-validator in auth/admin flows
- Admin access gate based on configured ADMIN_EMAIL
- Disabled account checks on login
- Generic error handling with reduced detail in production

Additional Guardrails:
- Auth middleware preserves intended destination via req.session.returnTo
- Concurrent user limiter can block new logins/registers if max active reached

7) ADAPTIVE QUIZ AND LEARNING LOGIC
==================================================
Quiz Generation:
- Quiz pool combines existing level quiz data plus lesson-derived questions (when enough lessons exist)
- Attempt question set is randomized
- Anti-repeat behavior avoids repeating same lead signatures and same full order across attempts

Adaptive Difficulty Recommendation:
- Uses recent attempts (default last 3) and response speed metrics
- Classifies suggested difficulty among easy/medium/hard
- Fast and high-scoring patterns push toward hard
- Low-scoring or slow patterns push toward easy

Scoring and Completion:
- Score computed as percent correct
- Passing threshold: 70%
- Progress row saved/updated per user+level
- Detailed attempt metrics saved for analytics

==================================================
9) CHATBOT (LESSON-GROUNDED ASSISTANT)
==================================================
Design:
- Available only to authenticated users
- Endpoint: POST /chatbot/ask

How it answers:
- Loads lessons from current content store
- Tokenizes question and lesson documents
- Computes cosine-like overlap score
- Selects top matches above minimum score threshold
- Extracts evidence sentences from lesson content
- Returns answer with citations and confidence value

Safety/Fallback Behavior:
- If confidence is too low, returns fallback "I don't know" style response
- Avoids pretending certainty without lesson support

Response payload fields include:
- answer
- confidence
- sources
- citations
- isFallback

==================================================
15) LIMITATIONS AND IMPROVEMENT AREAS
==================================================
Current limitations:
- SQLite is simple and reliable for small/medium usage, but not ideal for high concurrency at scale.
- No active automated test suite configured in package scripts.
- In-memory concurrent user limiter is process-local (not shared across multiple instances).
- Some documented env vars are not fully wired into quiz behavior at runtime.

Possible future enhancements:
- Add real test suite (unit/integration/e2e)
- Move to managed SQL database for scale
- Add distributed session/concurrency controls for multi-instance deployment
- Expose adaptive quiz settings through config/env and admin UI
- Add exportable analytics and localization support
